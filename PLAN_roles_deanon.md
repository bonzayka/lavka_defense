# План: права ролей + пер-юзерные права + деанон-скан каналов

## Часть 1 — роли из бота не работают на кнопках и части команд (БАГ)

**Корень:** `_admin_only()` (bot.py:2486) проверяет только `is_admin` (настоящий TG-админ),
а колбэк-кнопки (`on_moderation` 2169, `on_clearreq` 2311, голосование 2444) — тоже
голый `is_admin`. Поэтому носитель роли из бота не проходит. Текстовые `/mute` и т.п.
работают, потому что используют `_can(message, "mute")`.

**Правки:**
- `on_moderation` (2169): заменить `is_admin` на проверку права под конкретное действие
  (ban→`can(...,"ban")`, mute→`"mute"`, warn→`"warn"`, kick→`"kick"`). Кнопка «beru контроль»
  уже на `can`.
- `on_clearreq` (2311): `is_admin` → `can(gid, uid, "requests")`.
- Голосование `on_vote` (2444): админский 👎-вето → `can(..., "ban")` (право отменять).
- `/info` и справочные команды: ввести `_staff_only(message, perm=None)` — пускает TG-админа
  ИЛИ носителя любой роли (perm=None), либо с конкретным правом. `/info`, `/history`,
  `/diag` и прочее чтение → `_staff_only` без права (любой персонал). Наказания оставляем
  на `_can(..., perm)`.
- Проверить остальные `_admin_only` (список из 30) и раздать корректное право или
  «любой персонал», чтобы модератор видел то, что должен.

## Часть 2 — пер-юзерный оверрайд прав (жмёшь на человека → убрать лично ему)

**storage.py:** новый слой `user_perms` (str(uid) -> список прав), поверх роли.
- `get_user_perms_override(uid) -> list|None`, `set_user_perms(uid, list)`, `user_perms_all()`.
- `has_perm(uid, perm)` в bot.py: если есть пер-юзерный оверрайд — берём его, иначе права роли.

**Панель:** в `asg_keyboard` тап по строке сейчас снимает роль. Меняем: тап открывает
карточку юзера `panel:uperm:<uid>` с тумблерами прав (как `role_perm_keyboard`, но для
этого юзера; старт = текущие эффективные права), кнопки «Сбросить к роли» и «Снять роль».
Новые колбэки: `uperm` (открыть), `up:<uid>:<perm>` (тумблер), `upreset:<uid>`.

## Часть 3 — авто-деанон-скан каналов/юзернеймов через мой аккаунт (userbot)

**Триггер:** авто — в `on_message`/`TrackMiddleware` ловим t.me-ссылки и @упоминания в
сообщениях обычных участников (не персонал). Только каналы/чаты, не юзеры-люди.

**Новый модуль `channel_scan.py`** (рядом с userbot.py, тоже опционален под Telethon):
- `resolve_and_scan(target) -> dict`: через userbot-клиент `get_entity(target)`;
  если это Channel/Chat и `participants_count < config.DEANON_CHANNEL_MAX` (=100) —
  читаем последние N постов (`iter_messages`, limit=config.DEANON_CHANNEL_MSGS=50),
  прогоняем каждый текст через `textguard`-стоп-слова (открытые+скрытые) И `deanon.is_deanon`.
  Возвращаем {'hit':bool, 'reason':str, 'title':..., 'count':...}. Если участников ≥100
  или не канал — `{'skip':True}` (новостники игнорим, чтобы юзер зря не улетел).
- Переиспользуем `_client()`-подход из userbot.py (общий api_id/hash/session).

**Реакция в боте:** если `hit` — удаляем сообщение юзера, мутим его
(`apply_punishment(action_for('DEANON_CHANNEL_ACTION'))`, дефолт mute), в лог/панель
шлём «🕵️ В чате деанонер: <юзер> кинул <ссылку>, в канале найдено <причина>».

**Config (секция деанона):**
- `DEANON_CHANNEL_ENABLED=False` (env-off, требует userbot),
- `DEANON_CHANNEL_MAX=100` (порог участников — больше игнор),
- `DEANON_CHANNEL_MSGS=50` (сколько постов читать),
- `DEANON_CHANNEL_ACTION="mute"`,
- `DEANON_CHANNEL_NEWCOMERS_ONLY=True` (по умолчанию только новички, как в OCR-деаноне).

**Панель:** тумблер `DEANON_CHANNEL_ENABLED` (кат. «Антиспам»), действие
`DEANON_CHANNEL_ACTION`, число `DEANON_CHANNEL_MAX`.

**Риск (подтверждён пользователем):** userbot заходит/читает чужие каналы → Telegram
может забанить аккаунт за автоматизацию. Смягчаем: rate-limit (пауза между сканами),
кэш уже проверенных каналов (chat_id/username -> вердикт на TTL), скан только если
userbot.available(). Аккаунт расходный — ок.

## Тесты (tests.py)
- Часть1: `can()`/`_staff_only` — носитель роли `модератор` проходит mute-кнопку, но не ban.
- Часть2: пер-юзерный оверрайд перебивает права роли (снять mute лично при роли с mute);
  сброс возвращает к роли.
- Часть3: `channel_scan` — детект стоп-слова/PII в тексте постов (мок-список сообщений),
  порог участников (≥100 → skip), не-канал → skip. Резолвер регэкспа t.me/@ник.
